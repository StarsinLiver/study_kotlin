### 2.3 선택 표현과 처리 : enum 과 when

이번 절에서는 enum 와 when ㅇ르 설명한다. when 은 자바의 switch 를 대신하지만 훨 씬 더 강력하며 더 자주 사용되는 프로그래밍 요소이다. 또한 타입 검사와 타입 변환(cast)를 하나로 묶은 개념인 스마트 캐스트(smart cast)도 살펴본다.

### 2.3.1 enum 클래스와 enum 상수 정의

코틀린에서는 enum class 를 사용하지만 자바에서는 enum을 사용한다.

```kotlin
enum class Color {
    RED, ORANGE, YELLOW, GREEN, BLUE, INDIGO, VIOLET
}
```

색상을 이넘에 저장하는 것만으로도 이미 용이하지만 더 나은 일을 할 수 있다.

이넘 상수도 앞에서 봤던 일반적인 클래스와 마찬가지로 생성자와 프로퍼티 선언 문법을 사용할 수 있다. 여러분의 Color 이넘을 확장하기 위해 이 방법을 사용할 수 있다. 각 이넘 상수에 대해 r, g, b 값을 저장할 수 있다.

```kotlin
// Kotlin
enum class Color(
    val r: Int,
    val g: Int,
    val b: Int,
) {
    RED(255, 0, 0),
    ORANGE(255, 165, 0),
    YELLOW(255, 255, 0),
    GREEN(0, 255, 0),
    BLUE(0, 0, 255),
    INDIGO(75, 0, 130),
    VIOLET(238, 130, 238);

    fun rgb() = (r * 256 + g) * 256 + b;
    fun printColor() = println("$this is ${rgb()}")
}

// Java
public enum Color {

    RED(255, 0, 0);
    private final int r;
    private final int g;
    private final int b;

    Color(int r, int g, int b) {
        this.r = r;
        this.g = g;
        this.b = b;
    }
}
```

```kotlin
fun main() {
    println(Color.BLUE.rgb()) // 255
    Color.GREEN.printColor()  // GREEN is 65280
}
```

이 예제에서는 코틀린에서 유일하게 세미콜론(;)이 필수인 부분을 볼 수 있다. enum 클래스 안에 메서드를 정의하는 경우가 반드시 enum 상수 목록과 메서드 정의 사이에 세미콜론을 넣어야 한다.

### 2.3.2 when 으로 enum 클래스 다루기

자바에서 switch 문의 구성요소가 코틀린에서는 when 이다.

if 와 마찬가지로 when 도 값을 만들어 내는 식이다. 따라서 식 본문 함수에 when 을 바로 사용해서 when 식을 바로 반환할 수 있다.

```kotlin
fun getMnemonic(color: Color) {
    when (color) {
        Color.RED -> "Richard"
        Color.ORANGE -> "Of"
        Color.YELLOW -> "York"
        Color.GREEN -> "Gave"
        Color.BLUE -> "Battle"
        Color.INDIGO -> "in"
        Color.VIOLET -> "Vain"
    }
}

fun main() {
    getMnemonic(Color.RED)
}
```

이 코드는 color로 전달된 값과 같은 분기를 찾는다. 자바와 달리 각 분기의 끝에 break를 넣지 않아도 된다.

다른 분기를 사용하면 이넘 상수를 when 식에서 적절히 묶을 수 있다.

```kotlin
fun measureColor() = Color.ORANGE

fun getWarmthFromSensor(): String {
    val color = measureColor()
    return when (color) {
        Color.RED,
        Color.ORANGE,
        Color.YELLOW -> "warm (red = ${color.r})"
        Color.GREEN -> "neutral (green = ${color.g})"
        Color.BLUE,
        Color.INDIGO,
        Color.VIOLET -> "cold (blue = ${color.b})"
    }
}

fun main() {
    println(getWarmthFromSensor())
}
```

### 2.3.3 when 식의 대상을 변수에 캡쳐

앞의 예제에서 when 식의 대상은 color 라는 변수였고, 이 변수는 measureColor() 함수를 호출해서 얻은 결과였다. when 바깥의 코드를 불피요한 변수이므로 더럽히는 일을 방지하기 위해 when 식의 대상 값을 변수에 넣을 수도 있다.

```kotlin
fun getWarmthFromSensor(): String {
    return when (val color = measureColor()) {
        Color.RED,
        Color.ORANGE,
        Color.YELLOW -> "warm (red = ${color.r})"
        Color.GREEN -> "neutral (green = ${color.g})"
        Color.BLUE,
        Color.INDIGO,
        Color.VIOLET -> "cold (blue = ${color.b})"
    }
}
```

when 을 식으로 사용할 때마다 컴파일러는 when이 철저한지 (exhaustive) 살펴본다. 이는 모든 가능한 경로에서 값을 만들어내야 한다는 뜻이다.

### 2.3.4 when 의 분기 조건에 임의의 객체 사용

코틀린 when 은 실제로는 다른 언어의 비슷한 구성요소보다 훨씬 더 유연하다. 코틀린 when의 분기 조건에서는 임의의 객체를 사용할 수 있다. 앞에서 살펴본 팔레트에 있는 두 색삭을 혼합한 색상이 다시 팔레트에 속해 있는지를 알려주는 함수를 작성할 수 있다.

> when 분기 조건에 다른 여러 객체 사용하기

```kotlin
fun mix(c1: Color, c2: Color) {
    when (setOf(c1, c2)) {
        setOf(Color.RED, Color.YELLOW) -> Color.ORANGE
        setOf(Color.YELLOW, Color.BLUE) -> Color.GREEN
        setOf(Color.BLUE, Color.VIOLET) -> Color.INDIGO
        else -> throw Exception("Dirty color")
    }
}

fun main() {
    println(mix(Color.RED, Color.YELLOW))
}
```

c1과 c2가 RED 와 YELLOW라면 그 둘을 혼합한 결과는 ORANGE이다 .이를 구현하기 위해 집합 비교를 사용한다.

코틀린 표준 라이브러리에는 인자로 전달받은 여러 객체를 그 객체들을 포함하는 집합인 Set 객체로 만드는 setOf 함수가 있다. 집합(set)은 원소가 하나씩 모여있는 컬렉션이다.

또한 when 은 모든 분기 식에서 만족하는 조건을 찾을 수 없다면 else 분기를 계산한다.

### 2.3.5 인자 없는 when 사용

리스트 2.15가 약간 비효율적임을 눈치챈 독자가 잇을 것이다. 이 함수는 호출될때마다 함수 인자로 주어진 두 색상이 when 의 분기 조건에 있는 다른 두 색상과 같은지 비교하기 위해 여러 Set 인스턴스를 생성한다. 보통은 이런 것이 큰 문제가 되지 않는다. 하지만 이 함수가 아주 자주 호출된다면 가비지 컬렉터가 수거할 필요가 있는 짧게 살아있는 객체가 늘어나는것을 방지하고자 함수를 고쳐 쓰는 편이 낫다.

인자가 없는 when 식을 사용하면 불필요한 객체 생성을 막을 수 있다. 코드의 가독성은 조금 떨어지지만 성능을 더 향상시키기 위해 그 정도 비용을 감수해야 하는 경우도 자주 있다.

```kotlin
fun mixOptimized(c1: Color, c2: Color) {
    // when 에 아무 인자도 없다
    when {
        (c1 == Color.RED && c2 == Color.YELLOW) ||
        (c1 == Color.YELLOW && c2 == Color.RED) -> Color.ORANGE
        else ->
            Color.GREEN
    }
}

fun main() {
    println(mixOptimized(Color.RED, Color.YELLOW))
}
```

### 2.3.6 스마트 캐스트 : 타입 검사와 타입 캐스트 조합

C#을 아는 개발자라면 is가 낯익을 것이다. 자바 개발자라면 is 검사가 instanceof 와 같다고 식별할 수 있ㅇ르 것이다.

하지만 코틀린의 is 검사는 약간의 편의를 추가로 제공한다. 이 편의는 여러분이 어떤 변수의 타입을 확인한 다음에 그 타입에 속한 멤버에 접근하기 위해 명시적으로 변수 타입을 변환하지 않아도 된다는 점이다. 여러분은 타입을 검사한 변수를 마치 여러분이 검사한 그 타입의 변수인 것처럼 사용할 수 있다.

실제로는 컴파일러가 타입을 대신 변환해준다. 이런 경우를 스마트 캐스트라고 부른다.

```kotlin
class A(val a: Int)
class B(val b: Int)

fun main() {
    var pb = B(1)

    if (pb is A) {
        println("A 클래스 입니다.")
    } else if (pb is B) {
        println("B 클래스 입니다.")
    }
}
```

나중에 보겠지만 스마트 캐스트를 다른 코틀린 언어 기능인 널 가능성이나 코틀린의 디폴트로 파이널인 클래스와 함께 사용하기도 한다. 널 가능성은 7장에서 아주 자세히 다루고 디폴트로 파이널 클래스는 4.1.2절에서 살펴본다.

원하는 타입으로 명시적으로 타입 캐스팅하려면 as 키워드를 사용한다.

```kotlin
class B(val b: Int)

fun main() {
    val n = B(1) as B
}
```

어쩌면 짐작했겠지만 이런 구현은 아직 코틀린다운 코드라고 할 수 없다.

### when 과 스마트 캐스팅 활용

```kotlin
interface Expression {
}
class A(val a: Int) : Expression
class B(val b: Int) : Expression


fun smartCasting(ex : Expression) {
    when (ex) {
        is A -> println("A 클래스입니다.")
        is B -> println("B 클래스입니다.")
        else -> print("잘못된 값입니다.")
    }
}

fun main() {
    val pa = A(1) as A
    smartCasting(pa)
}
```

### 2.3.8 when의 분기에서 블록 사용

if 와 when 모두 분기에 블록을 사용할 수 있다. 그런 경우 블록의 마지막 문장이 블록 전체의 결과가 된다.

when의 각 분기를 블록으로 만들면 println 문을 추가할 수 있으며, 이때 각 블록의 맨 마지막에 있는 식이 그 블록이 반환할 값이 된다.

```kotlin
fun smartCasting(ex: Expression) =
    when (ex) {
        is A -> {
            println("A 클래스입니다.")
            // 이 식이 블록의 마지막 식이므로
            // 타입이 A이면 이 식의 값이 반환된다.
            ex.a
        }

        is B -> {
            println("B 클래스입니다.")
            // 이 식이 블록의 마지막 식이므로
            // 타입이 A이면 이 식의 값이 반환된다.
            ex.a
        }
    }


fun main() {
    val pa = A(1) as A
    val r = smartCasting(pa)
    println(r)
}

// 1
```

'블록의 마지막 식이 블록의 결과' 라는 규칙은 블록이 값을 만들어내야 하는 경우 항상 성립한다. 2.5.2절에서는 try 본문과 catch 절에서 같은 규칙을 쓰이는 예가 있으며 5.1.3절에서는 람다식에 이 규칙을 어떻게 적용하는지 설명한다. 하지만 2.1.3절에서 설명한 대로 이 규칙은 일반적인 함수에 대해서는 성립하지 않는다.

함수는 블록이 아닌 식을 본문으로 하는 함수이거나 그렇지 않은 경우 블록이 본문이되 블록 내부에 명시적인 return 문이 반드시 있어야한다.
