### 2.5 코틀린에서 예외 던지고 잡아내기

코틀린의 예외 (exception)처리는 자바나 다른 언어의 예외 처리와 비슷하다.

함수는 정상적으로 종료할 수 있지만 오류가 발생하면 예외를 던질 (throw) 수 있다. 함수를 호출하는 쪽에서는 그 예외를 잡아 (catch) 처리할 수 있다.

발생한 예외를 그 함수를 호출한 쪽에서 잡아 처리하지 않으면 함수 호출 스택을 거슬러 올라가면서 예외를 처리한느 부분이 나올 때까지 예외를 다시 던진다. (rethrow)

throw 키워드를 사용해 예외를 던질 수 있다.

```kotlin
throw IllegalArgumentException("IllegalArgument exception 입니다.")
```

코틀린에 new 키워드가 없음을 다시 한번 기억할 좋은 기회다. 예외 인스턴스를 만들 때도 아무런 차이가 없다.

### 2.5.1 try, catch, finally 를 사용한 예외 처리와 오류 복구

예제는 자바와 비슷하므로 따로 이야기를 하지는 않겠다.

```kotlin
import java.io.BufferedReader
import java.io.StringReader

fun readNumber (reader : BufferedReader) : Int? { // 함수가 던질 수 있는 예외를 명시할 필요가 없다.
    try {
        val line = reader.readLine()
        return Integer.parseInt(line)
    } catch (e : NumberFormatException) {
        return null
    } finally {
        reader.close()
    }
}

fun main() {
    val reader = BufferedReader(StringReader("x"))
    println(readNumber(reader))
}
```

자바 코드와 가장 큰 차이는 throws (이경우 s가 붙어있다) 절이 코틀린에 없다는 점이다. 자바에서는 함수를 작성할 때 함수 선언 뒤에 throws IOException을 붙여야 한다.

> 자바에서는 체크 예외가 메서드 시그니처의 일부다

```java
Integer readNumber(BufferedReader reader) throws IOException
```

이렇게 해야 하는 이유는 readLine 이나 close 가 발생할지도 모르는 IOException이 체크 예외 (checked exception)이기 때문이다.

자바 세계에서는 명시적으로 처리해야만 하는 유형의 예외를 체크 예외라고 한다. 우리가 함수를 던질 수 잇는 예외를 모두 선언해야만 하며, 여러분의 함수가 다른 함수를 호출할 경우에는 그 함수에 선언된 체크 예외를 모두 잡아 처리하거나 여러분의 함수에서도 다시 그 예외를 던질 수 있다고 선언해야만 한다.

다른 최신 JVM언어와 마찬가지로 코틀린도 체크 예외와 언체크 예외 (unchecked exception)을 구별하지 않는다. 함수가 던지는 예외를 지정하지 않고 발생한 예외를 잡아내도 되고 잡아내지 않아도 된다.

> 코틀린에서는 컴파일러가 예외 처리를 강제하지 않는다.

```kotlin
fun readNumber (reader : BufferedReader) : Int {
    val line = reader.readLine()
    return Integer.parseInt(line)
    reader.close()
}
```

> 왜 안잡아도 될까?

예를 들어 위 NumberForamtException 은 체크 예외가 아니다. 따라서 자바 컴파일러는 NumberFormatException을 잡아내도록 강제하지 않고 실제 실행 시점에 NumberFormatException이 발생하는 모습을 자주 볼 수 있다. 하지만 입력값이 잘못되는 경우는 흔히 잇는 일이므로 그런 문제가 발생한 경우 부드럽게 다음 단계로 넘어가도록 프로그램을 설계해야 한다는 시점에서 이는 불행한 일이다.

동시에 BufferedReader.close 가 IOException을 던질 수 있는데, 이 예외는 체크 예외이므로 자바에서는 반드시 처리해야 한다.

하지만 실제 스트림을 닫다가 실패하는 경우 대부분의 프로그램이 취할 수 있는 의미 있는 동작은 없다. 그러므로 이 IOException을 잡아내는 코드는 그냥 불필요하다.

이런 설계 결정으로 인해 여러분은 잡아내고 싶은 예외와 그렇지 않은 예외를 직접 결정할 수 있다. 예외를 잡아내고 싶은 경우 try-catch를 사용해 readNumber 함수를 작성할 수 있다.

### 2.5.2 try 를 식으로 사용

지금까지는 try 를 문으로만 사용했다. 하지만 try는 if나 when 처럼 식이기도 하다. 예제를 고쳐서 try 식의 장점을 살펴 try의 결과를 변수에 대입하자 단수노하를 위해 finally 절을 없애고 파일에서 읽은 수를 출력하는 코드를 추가하자

> try 를 식으로 사용하기

```kotlin
// void 함수
fun readNumber(reader: BufferedReader) {
    val number = try {
        val line = reader.readLine()
        Integer.parseInt(line)
    } catch (e: NumberFormatException) {
        return
    }
    println(number)
}

fun main() {
    val reader = BufferedReader(StringReader("not a number"))
    println(readNumber(reader))
}

// null
```

try 코드 블록의 실행이 정상적으로 끝나면 그 불록의 마지막 식의 값이 결과이다.

따라서 코틀린 예외 처리는 자바와 아주 비슷하다. 다만, 코틀린에서는 함수를 던질 수 있는 예외를 선언하지 않아도 된다.
