### 2.2 행동과 데이터 캡슐화 클래스와 프로퍼티

다른 객체지향 언어와 마찬가지로 코틀린도 클래스라는 추상화를 제공한다. 이 영역에서 코틀린의 클래스 개념은 이미 잘 아는 내용일 것이다.

하지만 코틀린은 활용하면 다른 객체지향 언어를 사용할 때보다 더 적은 양의 코드로 대부분의 공통적인 작업을 수행할 수 있다는 점을 알게 될 것이다. 이번 절은 클래스를 선언하는 기본 문법을 소개한다.

시작하기 위해 간단한 포조(POJO, Plain Old Java Object) 클래스 Person 을 정의하자

```java
// java
public class Person {
    private final String name;

    public Person(String name) {
        this.name = name;
    }

    public String getName() {
        return name;
    }
}
```

자바에서는 이런 클래스에도 상당히 긴 코드가 필요하다. 생성자 본문은 완전히 반복적이다.

1.5.1절에서 자바-코틀린 변환기를 소개했다. 자바-코틀린 변환기는 자바 코드를 같은 일을 하는 코틀린 코드로 자동 변환해준다. 변환기를 써서 방금 본 Person 클래스를 코틀린으로 변환해보자

```kotlin
class Person (val name: String)
```

여러분이 본 것처럼 코틀린은 클래스를 간결하게 정의할 수 있는 문법을 제공하며, 특히 코드가 없이 데이터만 저장하는 클래스에 대해 간결한 문법을 제공한다. 이런 클래와 자바 14이상의 비슷한 개념인 레코드(record)사이의 관계는 4.3.2절에서 살펴본다.

자바를 코틀린으로 변환한 결과 public 가시성 지정자(visiblity modifier)가 사라졌음에 유의한다. 코틀린의 기본 가시성은 public 이므로 이런 경우 지정자를 생략해도 된다.

### 2.2.1 클래스와 데이터를 연관시키고, 접근 가능하게 만들기 : 프로퍼티

클래스라는 개념은 데이터를 캡슐화하고 캡슐화한 데이터를 다루는 코드를 한 주체 안에 가두는 것이다.
자바에서는 데이터를 필드에 저장하며 멤버 필드의 가시성은 보통 비공개 (private)이다. 클라이언트가 클래스의 필드에 접근해야 할 피룡가 있으면 접근자 매서드 (accessor method)를 제공한다. 접근자 메서드에는 게터(getter)가 있고 세터 (setter)도 있을 수 있다.

자바에서는 필드와 접근자를 한데 묶어 프로퍼티 (property)라고 부르며 프로퍼티라는 개념을 활용하는 프레임워크가 많다. 코틀린은 프로퍼티를 언어 기본 기능으로 제공하며 코틀린 프로퍼티는 자바의 필드와 적븐자 메서드를 완전히 대신한다.

클래스에서 프로퍼티를 선언할 때는 val 또는 var를 선언한다. val로 선언한 프로퍼티는 읽기 전용이며 var로 선언한 프로퍼티는 변경이 가능하다.

```kotlin
// 코틀린은 (비공개 필드), (공개) 게터, (공개) 세터를 자동으로 만들어낸다.

class Person(
    val name: String,       // 읽기 전용 프로퍼티
    var isStudent: Boolean  // 쓸 수 있는 프로퍼티
)
```

```kotlin
fun main() {
    // 자바 new 키워드를 사용하지 않고 생성자를 호출한다.
    val person = Person("Bob" , true)

    // 프로퍼티 이름을 직접 사용해도 자동으로 게터를 호출해준다.
    println(person.name)
    println(person.isStudent)

    // 프로퍼티 이름을 직접 사용해도 자동으로 세터를 호출해준다.
    person.isStudent = false
    println(person.isStudent)
}
```

### 2.2.2 프로퍼티 값을 저장하지 않고 계산 : 커스텀 접근자

프로퍼티 접근자 커스텀 구현이 필요한 일반적인 경우로는 어떤 프로퍼티가 같은 객체안의 다른 프로퍼티에서 계산된 직접적인 결과인 경우이다.

직사각형 클래스인 Rectangle에서 width와 height를 저장한다면 너비와 높이가 같을때만 true 를 돌려주는 isSquare 프로퍼티를 제공할 수 있다.

이 프로퍼티는 프로퍼티에 접근할 때 계산을 할 수 있는 '온더고 (on the go)' 프로퍼티이므로, 정보를 별도의 필드에 저장할 필요가 없다. 대신 커스텀 게터를 제공할 수 있고, 이 커스텀 게터 구현은 프로퍼티에 접근할 때마다 객체가 정사각형인지 여부를 계산한다.

```kotlin
class Rectangle (val height : Int , val width : Int) {
    val isSquare : Boolean
        get() {
            return height == width;
        }
}
```

게터도 2.1.3절에서 살펴본 식 본문 함수 구분을 사용해 작성할 수 있다.

```kotlin
class Rectangle(val height: Int, val width: Int) {
    val isSquare: Boolean
        get() = height == width;
}
```

커스텀 게터를 정의하는 방식과 클래스 안에 파라미터가 없는 함수를 정의(코틀린에서는 맴버 함수나 메서드라고 부름)하는 방식 중 어느 쪽이 더 나은지는 다 알고있을 것이다. 구현이나 성능차이는 없다. 차이가 나는 부분은 가독성뿐이다.

### 2.2.3 코틀린 소스코드 구조 : 디렉터리와 패키지

코틀린은 클래스를 조직화하기 위해 패키지라는 개념을 사용한다. (자바 패키지와 비슷하다.) package 문이 있는 파일에 들어있는 모든 선언(클래스, 함수, 프로퍼티)은 해당 패키지 안에 들어간다.

```kotlin
package geometry.shapes
```

같은 패키지에 속해 있다면 다른 파일에서 정의한 선언일지라도 직접 사용할 수 있으나 다른 패키지에 정의한 선언을 사용하려면 해당 선언을 불러와야 한다.

파일 맨 앞의 package 문 아래 import 키워드를 사용해서 다른 패키지를 불러 올 수 있다.

```kotlin
package geometry.shapes

import geometry.shapes.Rectangle
```

패키지 이름 뒤에 .\*을 추가하면 패키지 안의 모든 선언을 임포트 할 수 있다.
