### 7.10 안전한 호출 연산자 없이 타입 확장 : 널이 될 수 있는 타입에 대한 확장

널이 될 수 있는 타입에 대한 확장 함수를 정의하면 null 값을 다루는 강력한 도구로 활용할 수 있다. 어떤 메서드를 호출하기 전에 수신 객체 역할을 하는 변수가 null이 될 수 없다고 보장하는 대신, 메서드 호출이 null을 수신 객체로 받고 내부에서 null을 처리하게 할 수 있다. 이런 처리는 확장 함수에서만 가능하다. 일반 멤버 호출은 객체 인스턴스를 통해 디스패치(dispatch)되므로 그 인스턴스가 null인지 여부를 검사하지 않는다.

예를 들어 확장함수중 isEmptyOrNUll 이나 isBlankOrNull 메서드가 있다.

> 널이 될 수 있는 수신 객체에 대해 확장함수 호출하기

```kotlin
fun verifyUserINput(input : String?) {
    // 안전한 호출이 필요없다.
    if (input.isNullOrBlank())
        println("Please fill in the required fields")
}

fun main() {
    verifyUserINput(" ")
    // Please fill in the required fields
    verifyUserINput(null)
    // Please fill in the required fields
}
```

안전한 호출 없이도 널이 될 수 있는 수신 객체 타입에 대해 선언된 확장 함수를 호출 가능하다. isNullOrBlank는 널을 명시적으로 검사해서 ? 가 필요하지 않다.

> isNullOrBlank 살펴보기

```kotlin
public String?.isNullOrBlank(): Boolean {
    return this == null || this.isBlank()
}
```

함수 내부에서 this는 null이 될 수 있다. 따라서 명시적으로 null 여부를 검사하고 있다. 자바에서는 메서드 아느이 this는 그 메서드가 호출된 수신 객체를 가리키므로 항상 null이 이니다. 코틀린에서는 널이 될 수 있는 타입의 활장 함수 안에서는 this가 null이 될 수 있다는 점이 자바와는 다르다.

앞에서 살펴본 let 함수도 널이 될 수 있는 타입의 값에 대해 호출할 수 있지만 let 은 this 가 null 인지 검사하지 않는다. 널이 될 수 있는 타입의 값에 대해 안전한 호출을 사용하지 않고 let 을 호출하면 람다의 인자는 널이 될 수 있는 타입으로 추론된다. 이는 값이 null 인지 여부와 관계없이 람다가 호출된다는 의미이기도 하다.
